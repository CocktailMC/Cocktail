# Cocktail Manager WEBUI · 三方向共同设计 Spec

**产出**: 高保真**管理端交互原型**（不是营销落地页、不是 PPT、不是改生产 React）  
**视口**: 截图统一 **1440×900**；首屏必须在 900px 高内读得懂机群态势  
**交付**: 单文件 HTML（纯 HTML/CSS + 最少量 JS 做屏切换）；logo 必须 base64 内嵌  
**语言**: 中文 UI 文案 + 英文产品名；中文引号用「」  
**日期假设**: 2026-09-13；示例通道 `edge-26.10`

---

## Assumptions（用户原话只有「重新设计 WEBUI」，以下为 best judgment，标在此）

1. **对象是现有 `admin/` 控制面**，不是昨天的 Edge/Scroll 介绍页。
2. **形态是可点击原型**：至少能在「机群主界面 / 实例仪表盘 / 控制台 / 网络」四屏间切换；不接后端。
3. **覆盖深度**：主路径 hi-fi；创建实例 / 登录 / 文件管理器用同一视觉语法点到即可，不把 20 个次级页做完。
4. **文案与模块只来自 README + 现有页面**，不发明 RBAC 多租户、S3 备份、Prometheus 等方案里尚未落地的能力。
5. **示意机群**（4 个实例）仅用于把布局撑住，页脚或角落标注「示意数据 · 非生产」。不写假用户数、假评分。

## 产品是什么

Cocktail Manager 是 CocktailMC 的 Minecraft 控制面管理端。服主打开它，是来**看机群还活着没有、对某一杯（实例）倒酒或封口、读控制台、必要时踢公网连接**——不是来逛功能目录。

现有 UI 的问题（从源码结构读出，作为 redesign 的靶）：顶栏 + 左栏机群导航 + 进入实例后出现第三层 subnav，层级深、卡片+FontAwesome 图标堆叠、主界面把事件/健康/统计/Docker/插件源/服务器列表纵向拼盘，5 秒内找不到「哪杯酒洒了」。

## 目标受众与使用场景

- **主受众**：中文 Minecraft 小服主，Windows 单机/小机群，笔记本 1m 距离，一天要开几次面板看 TPS 和有没有人在刷。
- **次受众**：给 Cocktail 提 PR 的贡献者，需要一眼看出热接管、网络防护不是「又一个 Pterodactyl」。
- **场景**：开机看哪几个在跑 → 点进崩溃的测试服读控制台 → 公网连接异常时去网络页踢人。
- **情感基调**：专业、可追溯、有工坊温度。不轻浮成酒吧海报，不冷成云厂商灰蓝。运行中偏活/流动（青柠+奶油），停止偏凝固（冰蓝结构），崩溃是唯一警报。
- 气质关键词：**吧台 / 装瓶 / 热接管 / 可追溯 / 调酒师工具**。

### 每版必须有的结构

1. **真 logo** + 产品名 Cocktail + 通道徽章 `edge-26.10`
2. **机群态势首屏**：4 个实例的状态一眼可分（运行/停止/崩溃）；崩溃的「测试」必须是第一视觉锚点之一

4. **进入实例**后能看到仪表盘指标 + 切到控制台、网络
5. **热接管**在主生存上写出来，这是竞品没有的词
6. **页脚或状态条**：Apache-2.0 · 本机 `127.0.0.1:11011` · 示意数据

## 视觉母题（form 必须从这里长出来）

别人套不到的结构：**吧台上一排放着的杯子。** Logo 已是隐喻——奶油酒液（流动的进程）盛在冰蓝杯体（控制面/容器）里，青柠是活点（运行中）。崩溃 = 酒洒了，不是一个红 badge 而已。

- 运行中：液面在、青柠点睛、数字在呼吸
- 已停止：空杯/封口、冰蓝结构、数字是破折号
- 崩溃：洒出、锐利警告、但不要整页血红
- 热接管：同一杯酒没倒掉，只是换了调酒师（控制面重启）

**form 来自内容的哪里**：来自「单机多实例 + 热接管 + 酒杯 logo」，不是来自「Dashboard 模板」。

色彩：奶油与冰蓝取自 logo；青柠只给「活着」；海军 `#0F4C81` 可作结构色但不要铺成 Azure。

## 输出格式与尺寸（三版统一）

- 单文件 `.html`，`file://` 双击能开
- 设计宽 1440，首屏高 900；正文 ≥14px（中文建议 15–16），标签 ≥12px，正文对比度 ≥4.5:1
- Logo：读取 `d:\Cocktail\design\webui\assets\logo-b64.txt` 写成 `<img src="data:image/png;base64,...">`
- 存盘：`d:\Cocktail\design\webui\design-demos\<逻辑名>.html`
- Google Fonts 允许。`text-wrap: pretty`。不要 React/Tailwind CDN。不要 stock 图。
- 交互：按钮切换 `data-screen`，不要 `scrollIntoView`。
- 可访问：状态不只靠颜色（文字：运行中/已停止/崩溃）。

## 三版布局骨架必须互异（硬）

由各 agent 的逻辑段指定。禁止共用「顶栏+左导航+卡片网格」只换色换字体。

## form 五问（已答，三版共用）

- **叙事角色**：hero = 机群吧台态势；实例屏 = 这一杯的酒谱；控制台 = 工艺现场；网络 = 谁进了店门。
- **观众距离**：1m 笔记本。
- **视觉温度**：工坊冷静，崩溃时才升到警报。
- **容量**：首屏必须同时看见 4 杯 + 控制面活着 + 一条崩溃事件；不许只放一个大数字。
- **视觉母题**：吧台上的杯子（见上）。
